# 2026-08-20 — iOS 2.0 light-mode correction prompt (Claude Design)

**Artifact record.** This is the prompt that produced the reconciled dark⇄light token
map (`4c`) in the Claude Design project `# 3D Print Assistant Redesign`. Kept for the
same reason the two 2026-08-19 prompts are kept: it is the artefact a design run
consumed, and the run's output is only interpretable against it.

**Consumed:** 2026-08-20. **Outcome:** all six asks addressed; every ratio independently
re-verified and passing. See
[`../superpowers/specs/2026-08-20-ios-2.0-quiet-instrument-panel-design.md`](../superpowers/specs/2026-08-20-ios-2.0-quiet-instrument-panel-design.md).

**Preceded by:** [`2026-08-19-ios-2.0-redesign-prompt-v2-claude.md`](2026-08-19-ios-2.0-redesign-prompt-v2-claude.md)
(the kickoff that produced `1a`–`3a`) and an interim light-mode ask that produced a first
`4c` with three failing colours — this prompt is the correction pass on that.

---

```
Refine the light theme in 4c (Token map · dark ⇄ light). Keep the "re-ink, not
invert" direction, the Daylight Workbench name, and the 4a/4b artboards — this is
a correction pass on the palette, not a redesign.

I independently recomputed every WCAG ratio in 4c. Your #007A56 claim (5.4:1) is
accurate — 5.36:1. Three others fail and need new values.

1. FIX THREE FAILING COLORS. Targets are AA body (4.5:1) against BOTH
   backgrounds — card #FFFFFF and canvas #F2F3EF, not just white.

   - WARNING #D94F21 = 4.13:1 on white. FAILS. This token marks "REQUIRED" in
     the gear builder (2a) — it is required reading, so 3:1 large-text is not
     acceptable. Darken it.
   - INFO/NEW #0B87B8 = 4.06:1 on white. FAILS. Used for news badges and "NEW".
   - textTertiary under your ink/N+8% rule = 2.75:1, below even the 3:1
     large-text floor, and worse than the dark theme's 3.2:1. Either raise the
     light tertiary alpha until it clears 3:1, or state in the sheet that it is
     decorative-only and may never carry text a user reads.

   Your ink/N+8% rule is fine for textSecond — it lands at 5.08:1. Keep it.

2. RECONCILE WITH THE SHIPPED WEB APP. The web app already ships a light theme
   and it disagrees with yours in every row. Neither is uniformly better, so
   produce ONE palette taking the stronger value per row and mark which source
   won. Measured ratios on white:

     token   yours              web (style.css)
     green   #007A56  5.36:1    #009a6a  3.60:1     <- yours wins
     orange  #D94F21  4.13:1    #d04a14  4.50:1     <- web wins, still weak
     purple  #6A5AE8  4.95:1    #5648d4  6.42:1     <- web wins
     link    #0B87B8  4.06:1    #0b7fc4  4.33:1     <- both fail, fix both
     canvas  #F2F3EF            #f2f2f7
     card    #FFFFFF            #ffffff            <- only agreement
     ink     #101613            #0f0f1a

3. THE CTA RULE NEEDS TO BE EXPLICIT. You keep #00E5A0 unchanged in light as
   "the brand moment." As a filled button with #04231A on it that is 10.09:1 and
   fine. But #00E5A0 as text, icon, thin border or status dot on white is
   1.65:1 — invisible. 4b currently says "dots and glows stay bright green."
   State the rule in the token sheet: in light, CTA green is FILL-ONLY. Then
   give a separate light value for any green that must read as a mark — status
   dots, ONLINE badges, the "yours" gear border.

4. ADD THE SIX MISSING TOKENS. 4c covers 8 tokens; the dark sheet has more.
   Give explicit light hexes (not just the alpha rule) for:
     - elevated       (dark #18181D)
     - onPrimary      (dark #04231A — confirm it is unchanged)
     - hairline       (dark white 7%)
     - borderActive   (dark white 12%)
     - primaryRamp    100/45/10/5 — the 10% and 5% washes are near-invisible on
                      white, so give real light values, not the same percentages
     - warning + info TEXT tints (dark has #FF8A5E and #A89DFA)

5. RE-RUN THE SELF-CRITIQUE (CRIT) FOR LIGHT. It currently reports dark-mode
   numbers only. Add a light column with computed ratios for every pair, against
   both #FFFFFF and #F2F3EF. Flag your own failures the way you did for dark.

6. CONFIRM THE AUTO BEHAVIOUR. The Appearance sheet offers three options. State
   explicitly that "Auto" follows the iOS system setting
   (@Environment(\.colorScheme)) and that the @AppStorage key stores an explicit
   override only, with Auto as the default for new installs.

Return the updated 4c plus the revised CRIT. Do not change 1a-1o, 2a or 3a.
```

## What it returned

All six addressed. Independently re-verified 2026-08-20 — every token clears its bar:
`ink` 18.32/16.44 · `signalText #007A56` 5.36/4.81 · `signalMark #009468` 3.86/3.47
(3:1 non-text) · `info #077099` 5.55/4.98 · `pro #5648D4` 6.42/5.76 ·
`warning #BF4515` 5.15/4.62 · `onPrimary` 10.09 on CTA. Where its own sheet differs it
under-claims rather than over-claims.

Notable: it split the green into `signalText` / `signalMark` / `ctaFill` rather than
forcing one value to serve all three roles, and it recommended shipping the reconciled
values back to the web theme — which independently fixes two live AA failures there.
