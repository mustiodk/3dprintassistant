>>> START >>>

You are a senior product designer redesigning **3D Print Assistant** (3DPA) — an
iOS app (SwiftUI, dark-mode only) that generates optimized slicer profiles for
3D printing hobbyists. Free, no account, privacy-first, live on the App Store.
Solo developer owner. Deliverables are mockups + a design-token sheet, not code.

**The current design is attached** — that's the starting point. Evolve it; don't
discard the brand. Anchor colour is `#00e5a0`. Fonts: Syne (headings/brand),
DM Mono (numeric/technical values), system font for body.

I've already locked a direction in an earlier exploration elsewhere. I'm not
showing you those visuals — I want your interpretation of the same decisions.

## Why redesign now

The app is entering 2.0: **My Gear**, **Filament Inventory** (paid Pro), an **AI
print-expert chat** (prepaid credits), and first real monetization. Home is
already crowded; bolting 2.0 onto it makes it worse. Redesign first.

## Locked decisions

**Direction — "Quiet Instrument Panel."** Technical precision, high-density
utility, thin borders, mono type for anything spec-like. Reads like well-made
measurement equipment, not a consumer lifestyle app. Green is a signal colour,
not a wash.

**Navigation — both layers.** Home is a full command center, *and* a global
bottom tab bar on every other screen so 2.0 features are always one tap away:
`Home · AI Expert · Inventory · Workshop · Feedback`. (Naming isn't locked —
argue for better.)

**My Gear — the marquee interaction.** A *gear* = brand + printer + nozzle +
filament type that the user owns. Users have several, and **different gears
often share the same brand and printer**, differing only in nozzle and/or
filament (same X1C with 0.4 standard + PLA, and again with 0.6 hardened +
PETG). Gear cards must make that legible at a glance — the printer name alone
won't differentiate them.

- One gear is default and prominent on Home.
- **Exactly one gear is active at a time** — quick-select, not multi-select.
- Home shows the **top 3**; more than three adds a **"show more"** affordance
  opening an **overlay** where the user picks the gear for this configuration.
- Selecting a gear **pre-fills the hardware half** of the 5-step wizard.

**Do not over-collapse this:** a gear does *not* produce a profile by itself.
Hardware is a gear; **intent is per print**. The user still answers what they're
printing, surface quality, strength, speed, environment before generating. So
the flow becomes *open → gear loaded → answer intent → generate*, and the Home
CTA must mean "continue with this gear," not "generate now."

**Workshop is not a catalog.** It's the user's own saved shortcuts: after
configuring, the app shows the resulting print + filament settings; if the user
likes them they tap a **star** to save that profile under a name, for reuse and
export. Design it as a personal, technical, list-shaped repository.

## Screens

1. **Home — command center**, two states: first-run (clean hero, one CTA) and
   returning-user (default gear prominent, top-3 switch, entries to AI Expert /
   Inventory / Workshop, a quiet **"N new printers added"** affordance since the
   catalog grows weekly, and a tip-jar + future Pro surface that's present but
   never nagging). Utility links collapse into a quiet footer.
2. **Gear overlay** — the "show more" selection surface.
3. **Brand picker** — step 1 of the wizard (brand → printer → material → nozzle
   → goals). Today's big cards feel heavy and unnecessary; make it **delicate
   and beautiful**. ~14 brands plus a "more" tier. The **step progress indicator
   is a priority element**. Show it in **two treatments so I can compare**:
   **(a) brand-identity** — real logotype character (Bambu Lab, Creality, Prusa,
   Anycubic, QIDI, Elegoo); **(b) utility** — restrained, uniform, typographic.
   Also show the 2.0 state where the user's own gear surfaces first.
4. **The bottom tab bar as a system** — active state, and how it coexists with
   the wizard's step progress.

## Taste (binding)

Smooth, minimalistic, functional. **Delicate. Crisp. Clean over flashy.**
Micro-details matter — spring-feel selection, staggered reveals, smooth
transitions. **Motion is part of the design**: annotate what springs, staggers
and fades, with rough durations and curves. Monetization reads premium-quiet,
never bazaar.

## Constraints

Vanilla SwiftUI only — no shaders, no heavy assets. System font + Syne + DM Mono.
No external images (CSS/SVG stand-ins fine). **Danish strings run ~20% longer** —
nothing may clip. WCAG AA on dark. Brand stays recognizable, though whether the
current logo and two-line title survive on the new Home is your call — argue it.

## Deliverables

1. Up to **3 questions**, only if an answer would materially change the design.
   Otherwise start.
2. A **single-file interactive HTML mockup in an iPhone frame (390×844)** as an
   artifact. Real data — real printer/brand names, plausible gear names, real
   materials (PLA Basic, PETG HF, ABS, TPU 95A) and nozzles (0.2 / 0.4 standard
   / 0.4 hardened / 0.6).
3. Make it **navigable** — I want to tap between Home, the gear overlay, both
   brand-picker treatments and the tab destinations, and feel the flow.
4. **Colour:** keep `#00e5a0` as anchor or argue for an evolved palette.
5. A **design-token sheet** — colours, type scale, spacing, radii, border
   weights, motion durations/curves — ready to translate to SwiftUI.

Show me one thing at a time; I'd rather react to a real screen than approve a
description.
