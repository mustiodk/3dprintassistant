## Why we're redesigning

The app is entering 2.0: **My Gear**, **Filament Inventory** (paid Pro), an **AI
print-expert chat** (prepaid credits), and first real monetization. Home is
already crowded; bolting 2.0 onto it makes it worse. Redesign first, then build
2.0 into the new layout.

## Locked decisions

**Direction — "Quiet Instrument Panel."** Technical precision, high-density
utility, thin borders, mono type for anything spec-like. Should read like
well-made measurement equipment, not a consumer lifestyle app. Green is a
signal colour, not a wash.

**Navigation — both layers.** Home is a full command center, *and* a global
bottom tab bar on every other screen so 2.0 features are always one tap away:
`Home · AI Expert · Inventory · Workshop · Feedback`. (Naming isn't locked —
argue for better.)

**My Gear — the marquee interaction.** A *gear* is a hardware combination the
user owns: brand + printer + nozzle + filament type. Users have several, and
**different gears often share the same brand and printer**, differing only in
nozzle and/or filament — the same X1C with 0.4 standard + PLA, and again with
0.6 hardened + PETG. Gear cards must make that difference legible at a glance;
the printer name alone won't do it.

- One gear is default and prominent on Home.
- **Exactly one gear is active at a time** — quick-select, not multi-select.
- Home shows the **top 3**. More than three adds a **"show more"** affordance
  opening an **overlay** where the user picks the gear for this configuration.
- Selecting a gear **pre-fills the hardware half** of the 5-step wizard.

**Workshop is not a catalog.** It's the user's own saved shortcuts: after
configuring, the app shows the resulting print + filament settings; if the user
likes them they tap a **star** to save that profile under a name, for reuse and
export. A personal, technical, list-shaped repository.

## The flow to design (design these as a connected sequence, not isolated screens)

**Returning user with gear:** opens the app → Home shows their default gear →
they either accept it or switch via the top-3 (or the overlay if they own more)
→ the wizard opens with brand, printer, nozzle and filament **already filled** →
they answer only the per-print intent questions (what they're printing, surface
quality, strength, speed, environment) → profile is generated → they can star it
into Workshop.

**Critical — do not over-collapse this.** A gear does *not* produce a profile by
itself. Hardware is a gear; **intent is per print**. So the Home CTA must mean
"continue with this gear," never "generate now."

**First-run user:** no gear yet → clean hero, one obvious CTA → the full 5-step
wizard (brand → printer → material → nozzle → goals).

## Screens

1. **Home — command center**, both states above. The returning state also
   carries: entries to AI Expert / Inventory / Workshop, a quiet **"N new
   printers added"** affordance (the printer catalog grows most weeks and new
   additions must stay discoverable), and a tip-jar plus future Pro surface
   that is present but never nagging. Utility links (Discord, website, version)
   collapse into a quiet footer.
2. **Gear overlay** — the "show more" selection surface.
3. **Brand picker** — step 1 of the wizard. Today's big cards feel heavy and
   unnecessary; make it **delicate and beautiful**. ~14 brands plus a "more"
   tier. The **step progress indicator is a priority element**.
   **Show two treatments side by side so I can choose:**
   **(a) brand-identity** — real logotype character (Bambu Lab, Creality, Prusa,
   Anycubic, QIDI, Elegoo); **(b) utility** — restrained, uniform, typographic.
   Also show the 2.0 state where the user's own gear surfaces first.
4. **Bottom tab bar as a system** — active state, and how it coexists with the
   wizard's step progress.

## States I want to see explicitly

- **Zero gear** (first run) · **one gear** · **eight gears** — the last is what
  forces the "show more" overlay, so prove the top-3 layout holds at both ends.
- **Loading** (the engine takes a moment on cold start) and **error** (engine
  failed to load, with a retry).
- **Empty Workshop.**

## Taste (binding)

Smooth, minimalistic, functional. **Delicate. Crisp. Clean over flashy.**
Micro-details matter — spring-feel selection, staggered reveals, smooth
transitions. **Motion is part of the design**: annotate what springs, staggers
and fades, with rough durations and curves. Monetization reads premium-quiet,
never bazaar.

## Constraints

Everything must be buildable in **vanilla SwiftUI** — no custom shaders, no
heavy asset pipelines. System font + Syne + DM Mono only; no external images
(vector stand-ins are fine for brand logos). **Danish strings run ~20% longer
than English** — nothing may clip or truncate. WCAG AA contrast on dark.
iPhone portrait only. The brand must stay recognizable to existing users,
though whether the current app logo and two-line title survive on the new Home
is your call — argue it either way.

## How to work with me

1. Ask up to **3 questions** first, but only where an answer would materially
   change the design.
2. Build the flow, then let me react screen by screen. **Name layers and screens
   clearly** — this goes to implementation afterwards.
3. Keep `#00e5a0` as the anchor, or argue for an evolved palette — show both if
   it's worth it. It must still feel like 3DPA.
4. When you're done, **critique your own work**: contrast ratios, tap-target
   sizes, information hierarchy, and anything that will be awkward in SwiftUI.
5. Finish with a **design-token sheet** — colours, type scale, spacing, radii,
   border weights, motion durations and curves — in a form I can translate
   directly into SwiftUI.
