>>> START >>>

You are a senior product designer doing a visual redesign for **3D Print
Assistant** (3DPA) — an iOS app (SwiftUI, dark mode only) that generates
optimized slicer profiles for 3D printing hobbyists. Free, no account,
privacy-first, live on the App Store. Owner is a solo developer. You are
designing, not shipping code: deliverables are mockups plus a design-token
sheet he can implement in SwiftUI.

I have already run one exploration with another tool and locked a direction.
**I am deliberately not showing you those visuals** — I want your own
interpretation of the same decisions. Everything below is settled unless
marked open.

## Context: why we're redesigning

The app is entering 2.0: **My Gear** (the user's own printers/filaments/nozzles
plus named gear setups), **Filament Inventory** (paid Pro feature), an **AI
print-expert chat** (prepaid credits), and first real monetization. Today's
Home screen has one row per feature and is crowded — twelve stacked elements,
five of them low-value links sitting at the same visual weight as the primary
CTA. Adding 2.0 to that would make it worse. So: redesign first, build 2.0 into
the new layout.

## Current design system (evolve it, don't discard it)

- Background `#0a0a0b` · surface `#111114` · elevated `#18181d`
- Primary/CTA green `#00e5a0` · warning orange `#ff6b35` · info purple `#7b6ef6`
- Accent cyan `#4ed6ff` · borders `white @ 7–12%`
- Text: white / 60% white / 30% white
- Fonts: **Syne** (bold — headings, brand) · **DM Mono** (parameter values and
  technical readouts) · system font for body/UI
- Radius 10–16pt, continuous corners
- Today's feel: dark, techy, neon-green terminal

## LOCKED: the design direction

**"Quiet Instrument Panel."** Technical precision and high-density utility —
thin borders, mono type for anything numeric or spec-like, a pro-tool
aesthetic. It should read like well-made measurement equipment, not like a
consumer lifestyle app. Restraint over decoration; the green is a signal
colour, not a wash.

## LOCKED: navigation model

Two layers, both present:

1. **Home is a command center** — full control from the home screen itself.
2. **A global bottom tab bar on every other screen**, so the 2.0 features are
   never more than one tap away from anywhere in the app:
   `Home · AI Expert · Inventory · Workshop · Feedback`

(Naming is not locked — "AI Expert" vs "Ask 3DPA" vs something better is your
call; argue for it.)

## LOCKED: My Gear — the marquee 2.0 interaction

A **gear** is a hardware combination the user owns: brand + printer + nozzle +
filament type. Users have several. Crucially, **different gears often share the
same brand and printer** and differ only in nozzle and/or filament — e.g. the
same X1C with a 0.4 standard + PLA, and again with a 0.6 hardened + PETG. Your
gear cards must make that distinction legible at a glance, because the printer
name alone won't differentiate them.

Behaviour:

- One gear is the **default** and is shown prominently on Home.
- **Exactly one gear is active at a time** for a configuration — this is a
  quick-select, not multi-select.
- Home shows **the top 3 gears** for fast switching. If the user has more than
  three, a **"show more"** affordance opens an **overlay** listing all of them,
  where the user picks the one to use for this specific configuration.
- Selecting a gear **pre-fills the hardware half of the configurator** — brand,
  printer, nozzle, filament type are already chosen, saving the returning user
  four of the five wizard steps.

**Important — do not over-collapse this.** Selecting a gear does *not* produce a
profile on its own. Hardware is a gear; **intent is per print**. The user still
answers the per-print questions (what are you printing, surface quality,
strength, speed, environment) before a profile is generated. So an active gear
turns the flow into: *open app → gear already loaded → answer intent → generate*.
Design the Home CTA accordingly — it should communicate "continue with this
gear," not "generate now."

## LOCKED: Workshop semantics (a real correction)

Workshop is **not** a browsable library of pre-made profiles. It is the user's
own **saved shortcuts**: after configuring everything, the app shows the
resulting print + filament settings; if the user likes that profile, they tap a
**star icon** to save it into their Workshop under a name they choose. It exists
for reuse and export. The app's own empty state says: *"Generate a profile, then
tap the star to save it here."* Design it as that — a personal, technical,
list-shaped repository of named saved configurations, not a catalog.

## Screens to design

**1. Home — command center.** Two states:
- *First run / no gear yet*: clean hero, one obvious CTA into the wizard.
- *Returning user with gear*: default gear prominent, top-3 quick switch,
  entries to AI Expert / Inventory / Workshop, a quiet **"N new printers added"**
  affordance (the printer catalog grows most weeks and new additions must stay
  discoverable), and a support/tip-jar plus future Pro surface that is present
  but never nagging. Utility links (Discord, website, version) collapse into a
  quiet footer.

**2. Gear overlay** — the "show more" surface listing all gears for selection.

**3. Brand picker** — step 1 of the wizard (brand → printer → material → nozzle
→ goals). Today it's a 2-column grid of large cards with circular monogram
avatars, and it feels heavy and unnecessary. Make it **delicate and beautiful** —
lighter rows or compact chips, tighter density, prominent search, considered
selection motion. ~14 brands plus a "more brands" tier. The **step progress
indicator is a priority element** and must stay legible.

**Show this screen in two treatments so I can compare:**
- **(a) Brand-identity**: real brand logotype character — Bambu Lab, Creality,
  Prusa, Anycubic, QIDI, Elegoo etc. rendered so they feel like the actual
  hardware brands.
- **(b) Utility**: restrained, uniform, monogram/typographic — brand as data,
  not as logo.

Also show the 2.0 state where the user's **own gear surfaces first** ("Your
gear") above the full catalog.

**4. The bottom tab bar as a system** — how it looks, how the active state
reads, how it coexists with the wizard's step progress.

Optional if it helps you argue the direction: Workshop list.

## Owner's taste (binding)

- Smooth, minimalistic, functional. **Delicate. Crisp. Clean over flashy.**
- Micro-details matter: spring-feel selection, staggered reveals, smooth
  transitions. **Motion is part of the design** — annotate what springs, what
  staggers, what fades, with rough durations and curves.
- Dark mode is primary; the app is dark-only today.
- Monetization must feel premium-quiet, never bazaar.

## Constraints

- Implementable in **vanilla SwiftUI** — no custom shaders, no heavy asset
  pipelines.
- System font + Syne + DM Mono only. No external images (CSS/SVG stand-ins are
  fine for logos).
- **Danish strings run ~20% longer than English** — leave room; nothing may
  clip or truncate.
- The brand should stay recognizable to existing users. Whether the current
  144pt app logo and the two-line "3D Print / Assistant" title survive on the
  new Home is **your call** — argue it either way.
- Accessible contrast on dark (WCAG AA).

## What I want from you

1. Ask me up to **3 questions**, but only if an answer would materially change
   the design. Otherwise start.
2. Build the screens as a **single-file interactive HTML mockup in an iPhone
   frame (390×844)**, rendered as an artifact. Real-feeling data — actual
   printer and brand names (Bambu Lab X1C, Creality K1, Prusa MK4, Elegoo
   Centauri Carbon…), plausible gear names, real materials (PLA Basic, PETG HF,
   ABS, TPU 95A) and nozzle sizes (0.2 / 0.4 standard / 0.4 hardened / 0.6).
3. Make it **navigable** — I want to tap between Home, the gear overlay, the
   brand picker's two treatments, and the tab destinations, so I can feel the
   flow rather than read a static board.
4. **Colour:** keep `#00e5a0` as the anchor, or argue for an evolved palette —
   show both if you think it's worth it. It must still feel like 3DPA.
5. Finish with a **design-token sheet**: colours, type scale, spacing, radii,
   border weights, motion durations and curves — in a form I can translate
   directly into SwiftUI.

Work iteratively and show me one thing at a time — I'd rather react to a real
screen than approve a description.
