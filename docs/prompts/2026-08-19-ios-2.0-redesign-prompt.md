# 2026-08-19 — iOS 2.0 redesign exploration prompt (for Fable)

**Purpose:** kickoff prompt for a visual-redesign brainstorm of the 3DPA iOS app,
run in a fresh claude.ai session on the strongest available model (Fable 5).
Prepared at the start of the 2.0 phase (My Gear / Inventory / AI Buddy /
monetization) so the redesign lands BEFORE Train 1 builds new UI onto the
current crowded Home screen.

**How to use:** copy everything between the markers into a new claude.ai chat.
Work iteratively — the prompt instructs the model to show directions as
interactive iPhone-frame mockups and ask one question at a time. Bring the
chosen direction back to a Claude Code session to fold into Train 1 execution.

---

>>> START >>>

You are a senior product designer doing a visual redesign exploration for
**3D Print Assistant** (3DPA) — an iOS app (SwiftUI, dark mode only) that
generates optimized slicer profiles for 3D printing hobbyists. Free, no
account, privacy-first. Live on the App Store; a sister web app shares the
same design language. Owner is a solo developer; you are designing, not coding
the app — deliverables are mockups + a design-token sheet he can implement in
SwiftUI.

## Why now

The app is entering its 2.0 phase: My Gear (own printers/filaments + named
Setups), Filament Inventory (paid Pro feature), an AI print-expert chat
(prepaid credits), and first-time real monetization. The current Home screen
has accreted one row per feature and is crowded; the new features would make
it worse. We redesign first, then build 2.0 into the new layout.

## Current design system (the starting point — evolve, don't ignore)

- Background `#0a0a0b` · surface `#111114` · elevated `#18181d`
- Primary/CTA green `#00e5a0` · warning orange `#ff6b35` · info purple `#7b6ef6`
- Accent cyan `#4ed6ff` (web only today) · borders `white @ 7–12%`
- Text: white / 60% white / 30% white
- Fonts: **Syne** (bold, headings/brand) + **DM Mono** (parameter values) +
  system font for body/UI
- Radius 10–16pt, continuous corners; subtle glows of green/purple on web
- Feel today: dark, techy, neon-green terminal vibe

## Screen 1 to redesign: Home (the crowded one)

Current stack, top to bottom, all on one screen: 144pt app logo · two-line
40pt title ("3D Print" white / "Assistant" green) · tagline · big green CTA
"Start configuring →" · a support/tip-jar card · "Workshop" text link ·
"Product updates" notification row with status text · engine-loading spinner
row (transient) · Discord link · website link · "Send feedback" link ·
version string. Twelve elements, five of them low-value links sitting at the
same visual level as the primary CTA.

What Home must ALSO accommodate in 2.0 (design homes for these now, even if
some ship later):

1. **Setup switcher** — the marquee 2.0 UX: a returning user's named Setups
   ("X1C · 0.6 hardened · PETG"), one is default, one tap applies it and
   collapses the 5-step configurator to just goals → generate. This becomes
   the returning user's primary action, coequal with or above the CTA.
2. **My Gear** entry (manage printers/filaments/nozzles pool + setups).
3. **AI buddy chat entry** — "Ask 3DPA" (later train, credits-based).
4. **Inventory** entry (later train, Pro).
5. A quiet **"N new printers added"** badge/affordance (catalog grows weekly).
6. Support/tip-jar + a future Pro purchase surface — monetization present but
   never nagging.

Design intent: first-run users see a clean hero + one obvious CTA; returning
users see their setups and go. Utility links (Discord, website, feedback,
version, updates) collapse into something quiet — a footer row, a settings/
ellipsis sheet, whatever fits the direction.

## Screen 2 to redesign: Brand picker (first step of the configurator)

Current: "Choose your brand" 28pt Syne title, then a 2-column grid of big
cards — each card is a circular monogram avatar + brand name, 24pt vertical
padding, 16pt radius, selected = green tint + border. ~14 brands plus a
"More brands" section. Owner verdict: **feels heavy and unnecessary — wants
it more delicate and beautiful.** Consider: lighter rows or compact chips, a
type-forward list with real brand wordmark feel, tighter density, search
prominence, motion on selection. The picker is step 1 of a 5-step wizard
(brand → printer → material → nozzle → goals) with progress dots — the step
indicator is a priority element and must stay legible.

Note for 2.0: once My Gear exists, the user's own brands/printers surface
first ("Your gear"), with the full catalog behind it — show that state too.

## Owner's taste (binding)

- Smooth, minimalistic, functional. Delicate. Crisp. **Clean over flashy.**
- Micro-details matter: spring-feel selection, staggered reveals, smooth
  transitions. Motion is part of the design — annotate it in the mockups.
- Dark mode is primary and the app is dark-only today.
- Monetization surfaces must feel premium-quiet, not bazaar.

## Your task

1. Ask up to 3 sharp questions if anything materially changes direction —
   otherwise start.
2. Propose **3 distinct design directions** (e.g. "quiet instrument panel",
   "editorial type-forward", "soft-depth glass") — one at a time, as a
   **single-file HTML mockup in an iPhone frame (390×844)** rendered as an
   artifact, showing Home (returning-user state with setups + first-run
   state) and the Brand picker. Fake data is fine; make it feel real
   (real printer/brand names: Bambu Lab X1C, Creality K1, Prusa MK4, etc.).
3. Color exploration is welcome: keep `#00e5a0` as the anchor OR argue for an
   evolved palette — show both if useful. Contrast must stay accessible
   (WCAG AA on dark).
4. Annotate intended motion (what springs, what staggers, what fades) as
   short labels or a notes panel in the mockup.
5. After the 3 directions, ask the owner to pick/mix, then refine the winner
   into: final mockups for both screens (all states) + a **design-token
   sheet** (colors, type scale, spacing, radii, motion durations/curves)
   ready to translate to SwiftUI.

Constraints: everything must be implementable in vanilla SwiftUI (no custom
shaders, no heavy asset pipelines); system font + Syne + DM Mono only; no
external images (CSS/SVG stand-ins fine); Danish strings run ~20% longer —
leave room. The brand should stay recognizable to existing users.
